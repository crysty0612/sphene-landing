Three Fundamental Architectural Advancements

1. Memory Footprint: Systems Engineering vs. Chromium Wrapper

Electron applications like Obsidian must instantiate a full Chromium rendering process, a V8 JavaScript virtual machine, and a Node.js runtime just to display text. As vaults grow to thousands of notes, memory consumption rapidly balloons beyond 1GB RAM. Sphene is written as a native compiled Go binary that operates continuously under 25MB of RAM at rest (<50MB with embedded WireGuard mesh relay). It leaves your CPU and RAM free for your code editors, Docker containers, and local LLM inferences.

2. Native Model Context Protocol (MCP) vs. Fragile Shell Hacks

To give AI agents (like Claude Desktop, Hermes Agent, or Cursor) access to an Obsidian vault, developers typically resort to running custom Python scripts, terminal piping hacks, or insecure community REST plugins. These solutions suffer from shell escaping bugs, lock contention, and high latency. Sphene exposes a first-class, typed JSON-RPC Model Context Protocol (MCP) server over stdio. Autonomous agents execute sub-millisecond searches, pinpoint facts with intra-document AST search, and stage updates cleanly.

3. The Differential Timeline ("Human Veto") vs. Silent Disk Overwriting

When an AI agent modifies a note in Obsidian, it writes directly to disk. A hallucinated or malformed edit can silently delete your carefully structured thoughts or corrupt frontmatter metadata. Sphene introduces the Differential Timeline: all agent-initiated modifications are intercepted and staged as structured AST diffs. You inspect the highlighted visual differences in the UI, and with one click approve or veto changes before any physical byte hits your drive.
